# Лабораторна робота №2 
**з дисципліни «Операційні системи з розподілом часу».**

Власна реалізація `malloc()`, `calloc()`, `realloc()` та `free()` мовою C на основі системних викликів `brk()`/`sbrk()`, `mmap()` та `munmap()`. Завдання: [open-education-hub / memory-allocator](https://github.com/open-education-hub/operating-systems/tree/main/content/assignments/memory-allocator).


## Реалізація

### Блоки

Кожен блок пам'яті починається зі структури `struct block_meta` (розмір, статус, вказівники `prev`/`next`), за якою йде корисне навантаження. Функції повертають адресу саме навантаження. Розмір структури і розмір навантаження вирівнюються до 8 байт, тому розмір заголовка дорівнює 32 байтам.

Статуси блоку:

- `STATUS_ALLOC` — зайнятий блок на купі;
- `STATUS_FREE` — вільний блок на купі, може бути використаний повторно;
- `STATUS_MAPPED` — блок, виділений через `mmap()`.

Блоки купи об'єднані у двозв'язний список у порядку адрес (`heap_head` … `heap_tail`). Блоки, виділені через `mmap()`, до списку не входять.

### Вибір між `brk()` і `mmap()`

- `os_malloc()`: якщо розмір блоку разом із заголовком менший за `MMAP_THRESHOLD` (128 КБ), пам'ять береться з купи, інакше — через `mmap()`;
- `os_calloc()`: те саме, але поріг дорівнює розміру сторінки (`getpagesize()`); пам'ять обнуляється через `memset()`.

### Передвиділення купи

При першому зверненні до купи один раз викликається `sbrk(128 КБ)`. Уся ця область стає одним вільним блоком, з якого далі нарізаються менші блоки. Це зменшує кількість викликів `brk()`.

### Алгоритм виділення на купі

1. Об'єднання всіх сусідніх вільних блоків (coalesce).
2. Пошук найкращого вільного блоку (find best): серед вільних блоків, яких достатньо за розміром, обирається найменший.
3. Якщо блок знайдено, він розбивається (split): залишок стає новим вільним блоком, якщо в нього вміщується заголовок і хоча б 8 байт даних.
4. Якщо підходящого блоку немає, а останній блок купи вільний, купа розширюється на `size - last->size` байт і останній блок збільшується.
5. Інакше купа розширюється на розмір нового блоку з заголовком, і блок додається в кінець списку.

### `os_free()`

Блок на купі лише позначається як вільний, пам'ять операційній системі не повертається. Блок, виділений через `mmap()`, звільняється через `munmap()`.

### `os_realloc()`

- `ptr == NULL` — те саме, що `os_malloc(size)`; `size == 0` — те саме, що `os_free(ptr)`;
- для блоку зі статусом `STATUS_FREE` повертається `NULL`;
- блок, виділений через `mmap()`, а також запит на розмір не менший за поріг, обробляються виділенням нового блоку, копіюванням даних і звільненням старого (`mremap()` не використовується);
- якщо новий розмір не більший за поточний, блок зменшується через split;
- якщо блок останній на купі, купа розширюється на потрібну кількість байт;
- інакше наступні вільні блоки приєднуються по одному, і після кожного кроку перевіряється, чи вистачає розміру; приєднані блоки залишаються об'єднаними, навіть якщо розміру зрештою не вистачило;
- якщо розширити блок на місці не вдалося, виділяється новий блок, дані копіюються, старий звільняється.

Результат кожного системного виклику перевіряється макросом `DIE()`.

## Збірка і тестування

Потрібні Linux x86_64, `gcc`, `make`, `python3`, `ltrace`, `valgrind`:

```bash
sudo apt install gcc make python3 python-is-python3 ltrace valgrind
```

Збірка бібліотеки:

```bash
cd src
make
```

Запуск усіх тестів (з перевіркою витоків пам'яті):

```bash
cd tests
make check
```

Запуск окремого тесту:

```bash
cd tests
python run_tests.py -d test-all
```
